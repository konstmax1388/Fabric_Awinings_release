# План переосмысления дизайна (без поломки функционала)

Документ фиксирует безопасный поэтапный rollout нового дизайна по принципу **Mobile First (375x667)** и правилу **один адаптивный компонент вместо дублей mobile/desktop**.

Связанные документы: [design.md](./design.md), [typography.md](./typography.md), [animations.md](./animations.md), [deliverables-and-acceptance.md](./deliverables-and-acceptance.md), [technical-debt.md](./technical-debt.md).

---

## Статус выполнения

- R1 (токены/типографика/контейнеры): **выполнен**.
- R2 (единая адаптивная геометрия витринных секций без дублей mobile/desktop): **выполнен**.
- R3 (калькулятор как единый компонент mobile/desktop): **выполнен**.
- R4 (motion/interaction слой с progressive enhancement): **выполнен**.
- R5 (Dark Premium full relayout всех публичных страниц): **выполнен**.

---

## 1) Цель и границы

### Цель

Пересобрать визуальную систему сайта как единый адаптивный организм: на мобильном плотный и тактильный, на десктопе расправленный и «натянутый», **без изменения бизнес-логики**.

### Что нельзя ломать

- Контракты API и формат payload (включая checkout, оплату, СДЭК, ЛК).
- Маршруты и публичные URL.
- Ключевые пользовательские сценарии: каталог, карточка, корзина, checkout, ЛК.
- Работу Django admin / staff-части, если не затрагивается явно.

### Технический принцип

- Запрещён паттерн двух версий одного блока (`mobile-*` + `desktop-*` с `display:none`).
- Разрешён паттерн одного блока с адаптивной компоновкой (`column -> row`, `wrap`, `scroll-snap` on/off).

## 2) Базовые дизайн-правила (из нового ТЗ)

### Mobile Master

- Базовый фрейм проектирования: **375x667**.
- Вся логика, иерархия и микротипографика формируются сначала на mobile.

### Типографика

- H1: `Unbounded` с масштабом от mobile к desktop через `clamp()`.
- Основной текст: `Manrope` с `clamp()` и стабильной читаемостью на всех ширинах.
- Числовые акценты (цены, KPI): `Unbounded`, масштабируемые через `clamp()`.

### Сетка и геометрия

- Mobile: одна колонка, фиксированные боковые поля.
- Desktop: центральная колонка с `max-width`, «резиновые» края.
- Переходы между состояниями только через layout-правила, без дублирования DOM.

### Калькулятор

- Mobile (<767): вертикальный scroll-snap визард из 3 секций.
- Desktop (>1024): те же 3 секции в одной строке (левая/средняя/правая колонка).
- Логика выбора/расчёта едина для обоих режимов.

### Анимации

- Общая модель событий: `pointer` + `hover` + `scroll` на одном наборе компонентов.
- Mobile и desktop отличаются триггерами, но не дублированием сущностей.
- Уважение `prefers-reduced-motion`.

## 3) Поэтапный rollout (безопасный)

## Этап R1. Токены и фундамент (без смены структуры страниц)

**Что делаем**

- Вводим дизайн-токены: палитра, радиусы, тени, типографическая шкала `clamp()`.
- Нормализуем базовые отступы/контейнеры.
- Добавляем технические utility-классы для адаптивной геометрии.

**Что не трогаем**

- Бизнес-логику компонентов и API-взаимодействие.
- Порядок шагов checkout и отправку данных.

**Критерий готовности**

- Внешний вид обновлён на уровне системы, функционал неизменен.
- Сборка frontend проходит, критических UI-регрессий нет.

---

## Этап R2. Каркас страниц и единая адаптивная компоновка

**Что делаем**

- Переводим ключевые секции на единый responsive layout без дублей.
- Обновляем hero, преимущества, базовые карточки под новую геометрию.
- Подготавливаем «резиновое натяжение» секций на широких экранах.

**Контроль**

- Проверяем сохранность интерактива: ссылки, CTA, якоря, роутинг.

**Критерий готовности**

- Один DOM-блок на сущность, переход mobile/desktop только через layout.

---

## Этап R3. Калькулятор (самый рискованный блок)

**Что делаем**

- Mobile-режим: scroll-snap визард из 3 шагов.
- Desktop-режим: те же шаги в 3 колонках (форма / размер / цена).
- Единый state и единые обработчики для обоих режимов.

**Контроль**

- Полный regression checkout: расчёт, валидации, отправка заказа.
- Совместимость с существующими интеграциями (оплата/доставка).

**Критерий готовности**

- Пользователь получает тот же результат заказа, независимо от ширины экрана.

---

## Этап R4. Motion/interaction слой

**Что делаем**

- Прогресс-эффекты, тактильные hover/tap-анимации, скролл-синхронизация.
- Отдельные fallback-поведения для слабых устройств и reduced-motion.

**Контроль**

- Нет блокирующих анимаций.
- Нет деградации доступности (фокус, таб-навигация, контраст).

**Критерий готовности**

- Анимации усиливают UX и не мешают оформлению заказа.

---

## Этап R5. Полировка и релиз

**Что делаем**

- Точечная шлифовка визуальных артефактов.
- Финальные smoke/regression-проверки.
- Подготовка релиз-заметки и rollback-плана.

**Критерий готовности**

- Дизайн полностью обновлён, ключевые сценарии стабильны.

---

## 4) Порядок внедрения по страницам

Рекомендуемая последовательность:

1. Главная (`Home`) и общие секции.
2. Каталог и карточка товара.
3. Корзина.
4. Checkout (последним крупным этапом).
5. Личный кабинет и второстепенные страницы.

Причина: сначала низкорисковые витринные экраны, затем транзакционные.

---

## 5) Definition of Done по каждому этапу

- Визуальные требования этапа выполнены по макету.
- Нет дублирующих mobile/desktop блоков.
- Нет изменений API-контрактов.
- Проходят обязательные проверки проекта для затронутого стека.
- Зафиксирован короткий changelog этапа и риски следующего шага.

---

## 6) Проверки перед каждым релизом этапа

- Frontend: `npm run build`.
- Backend (если затронут): `python manage.py check`.
- Функциональный smoke:
  - каталог/карточка,
  - корзина,
  - checkout,
  - ЛК заказов.
- Проверка адаптива минимум на ширинах: 375, 768, 1024, 1440.

---

## 7) Риски и меры

- Риск: визуальный рефакторинг заденет checkout.
  - Мера: checkout переводится отдельным этапом R3, с обязательным regression.
- Риск: избыточные анимации ухудшат UX.
  - Мера: progressive enhancement + reduced-motion + budget по производительности.
- Риск: появятся «двойные» компоненты под mobile/desktop.
  - Мера: код-ревью по правилу одного блока и адаптивной компоновки.

---

## 8) Принятые решения на текущий момент

- Работаем по Mobile First с master-фреймом 375x667.
- Внедряем редизайн итерациями, без «big bang» замены всего сайта за один релиз.
- Функциональная стабильность checkout и интеграций приоритетнее визуальной скорости.
