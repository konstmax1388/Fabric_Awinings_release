# Ozon Доставка (Seller API) и текущий сайт: соответствие

Зафиксировано: **2026-04-24** (сверка с публичными материалами dev.ozon: «Начало работы с Seller API», «Как подключить Ozon Доставку», «Ozon Доставка: подключение, настройка…», «Справочник методов Seller API для Ozon Доставки»).

## Два разных контура

| Официальный сценарий **Ozon Доставка** + **Seller API** | Реализация в этом репозитории |
|--------------------------------------------------------|------------------------------|
| Личный кабинет продавца: заявка на **Ozon Доставку**, **частное приложение**, скоуп `seller-api.ozon-logistics` (+ при необходимости product, posting, returns, report) | **Нет** привязки к OAuth / `api-seller.ozon.ru` / Client ID + токен продавца **для логистики** |
| `POST /v1/delivery/check` (телефон), карта/список ПВЗ, `POST /v2/delivery/checkout` (сроки, сплиты FBO/FBS) | **Нет** — чек-аут на витрине **не** вызывает эти методы; выбора ПВЗ/курьера по Seller API нет |
| `POST /v2/order/create` **после** подтверждения оплаты, с данными из чекаута | **Нет** — отдельный лог-заказ в Seller API не создаётся |
| Отслеживание постингов FBO/FBS, отмены, маркировки и т.д. | **Нет** — не интегрировано |
| **Альтернатива в доке:** путь **через Ozon Pay** (эквайринг + доставка одним пакетом) | **Да, ближе к коду** — используется **Ozon Acquiring (Ozon Pay Checkout)**, а не «голый» сценарий `v2/order/create` из справочника доставки |

## Что в коде сейчас (Ozon Pay / Acquiring)

- Хост: `https://payapi.ozon.ru` (или `OZON_PAY_API_URL` / `OZON_PAY_API_BASE_URL`), метод **`POST /v1/createOrder`**, подпись `requestSign` — см. [документацию Acquiring](https://docs.ozon.ru/api/acquiring/).
- Для способа доставки «Логистика Ozon» в корзине: **`MODE_FULL`**, **`deliverySettings: { isEnabled: true }`**, **`items`** (в т.ч. `sku` из карточек, поле `ozon_sku`), плюс настройки письма/телефона фискализации по необходимости — реализация: `api/services/ozon_acquiring.py`, `ozon_acquiring_cart.py`.
- Вебхук оплаты: `POST /api/webhooks/ozon-pay/`, обновление `CartOrder` по `extOrderID` — `api/views_checkout.py`.
- См. также: `docs/ozon-pay-env.md` в корне репозитория, настройки в админке (Ozon Pay, оформление, Ozon Доставка — UI и флаги).

**Итог:** витрина опирается на **эквайринг** с доставочными флагами в `createOrder`, а не на полный цикл **Seller API** из справочника **Ozon Доставка** (`v1/delivery/*`, `v2/delivery/checkout`, `v2/order/create`).

## Рекомендации из доки Ozon, которые **ещё** не реализованы на сайте

- Ранняя **проверка доставки** (`delivery/check`) по правилам и формату телефона.
- **Чекаут** перед оплатой (`v2/delivery/checkout`) с актуальным составом и сроками.
- Выбор **ПВЗ / курьер** и передача выбранного id/адреса **в** последующий **order/create** (у нас этот шаг в Seller API не вызывается).
- **Создание заказа** в логистике Ozon **только после** подтверждения оплаты — в доке отдельный метод; у нас деньги и «корзина в эквайринге» объединены в **Acquiring `createOrder`**, а не в `v2/order/create` Seller API.

## Если понадобится сценарий «как в справочнике 448»

Понадобится **отдельный** блок работ: OAuth (или схема с ключом из частного приложения), хранение токена, UI чек-аута, вызовы `delivery/check`, `delivery/checkout`, после вебхука оплаты — **`v2/order/create`**, хранение `order_number` и постингов в `CartOrder`, обработка отмен/статусов. Это **не** заменяет текущий Ozon Pay, а **добавляется** по согласованию с Ozon и с учётом варианта **«Ozon Pay + доставка»** из кабинета (если он вам выбран бизнесом).
