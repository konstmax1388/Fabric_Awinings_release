# Аудит и план доведения до прод-показа (v3.0.0)

## Baseline перед релизом

- Публичный фронтенд: `npm run build` проходит успешно.
- Основные сценарии smoke для проверки:
  - главная, каталог, карточка товара, корзина, checkout;
  - вход/регистрация пользователя;
  - Django admin (`/admin/`) и staff UI (`/staff/`).
- Критичные риски до правок:
  - нестабильный sticky на desktop из-за разных offset и layout-контекстов;
  - отсутствие parity CRUD для `StaticPage` в staff API;
  - HTML-контент из CMS/блога/товаров рендерится без серверной санитизации;
  - неунифицированный deploy pipeline (локальный скрипт и GitHub Actions расходятся);
  - недостаточный контроль версии билда на проде.

## Реализованные изменения в рамках полного плана

### 1) Sticky и layout consistency (desktop)

- Введена единая переменная высоты шапки `--site-header-height`, выставляемая в рантайме из `SiteHeader`.
- Sticky-offset унифицирован в ключевых местах:
  - каталог (aside),
  - карточка товара (правая колонка),
  - корзина (summary aside).

Результат: фиксированное «прилипание» без ручных `top-24/top-28` в разных страницах.

### 2) Согласованность двух админок (Django + staff)

- Добавлен Staff CRUD для `StaticPage`:
  - сериализатор,
  - ViewSet,
  - роут в `staff_urls`.

Результат: статичные страницы теперь редактируются консистентно не только через Django Admin.

### 3) Яндекс Метрика и безопасные snippet-поля

- Добавлены поля в `SiteSettings`:
  - `analytics_head_snippet`,
  - `analytics_body_start_snippet`.
- Поля выведены в секцию «Аналитика и SEO» в админке.
- Поля отдаются через публичный API в `analyticsYandex`.
- На фронтенде добавлен компонент `AnalyticsSnippets` для инъекции:
  - в начало `<head>`,
  - в начало `<body>`.

Результат: код счетчика/интеграции можно задавать из админки без хардкода ID в репозитории.

### 4) Lazyload и оптимизация изображений/тяжелых блоков

- Убрана лишняя блокирующая зависимость FontAwesome CDN из `frontend/index.html`.
- Для iframe-карты включен `loading=\"lazy\"`.
- Конструктор Яндекс.Карт загружается лениво через `IntersectionObserver`.
- В карточке товара заменен обычный `<img>` на `OptimizedImage` в блоке карты материалов.

Результат: меньше блокирующих ресурсов и более поздняя загрузка тяжелых блоков вне первого экрана.

### 5) Безопасность, антиспам и hardening

- Добавлена серверная санитизация HTML (`bleach`) и применение в:
  - staff-редактировании HTML товара,
  - staff-редактировании тела блог-поста,
  - публичной выдаче HTML (товар/блог/статичные страницы).
- Добавлен throttling для customer login (`auth_login` + throttled token view).
- Усилены security headers в settings:
  - `SECURE_CONTENT_TYPE_NOSNIFF`,
  - `SECURE_REFERRER_POLICY`,
  - `X_FRAME_OPTIONS`.

Результат: снижены риски XSS/перебора логина и повышена базовая защищенность ответов.

### 6) Deploy consistency и контроль версии

- GitHub Actions deploy синхронизирован с локальным сценарием:
  - `git reset --hard origin/main`,
  - сборка `frontend` + `admin-ui`,
  - атомарная замена `frontend/dist/staff`,
  - прогон Django migrate/collectstatic.
- В health endpoint добавлены:
  - `version`,
  - `gitSha`,
  - `builtAt`.
- Версия релиза повышена до `3.0.0`.

Результат: проще доказывать, какой именно билд стоит на проде, и меньше расхождений между каналами деплоя.

## Чеклист финальной демонстрации заказчику

- Очистить кэш браузера и проверить sticky header на desktop:
  - Home, Catalog, Product, Cart.
- Проверить, что snippet из админки появляется в DOM:
  - в `<head>`,
  - в начале `<body>`.
- Проверить `api/health`:
  - `version = 3.0.0`,
  - `gitSha` соответствует релизному коммиту.
- Проверить parity контента:
  - изменение `StaticPage` в staff отражается на публичке.
- Проверить формы на антиспам и ошибки:
  - корректные ошибки при невалидном вводе,
  - отсутствие регрессии отправки.
